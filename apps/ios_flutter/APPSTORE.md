# Рыцари и Замки — iOS (Flutter) → App Store

Приложение = Flutter-оболочка + твоя веб-игра **внутри** (папка `assets/www`).
Игра против ботов работает без интернета. Онлайн и аккаунты идут через Supabase.

> На Linux (Codespaces) iOS-приложение собрать нельзя. Нужен **Mac с Xcode**.

## 1. Один раз: подготовка Mac
1. Установить Xcode (App Store), открыть его один раз и принять лицензию.
2. Установить Flutter: https://docs.flutter.dev/get-started/install/macos
3. `flutter doctor` — все пункты для iOS должны быть зелёными (CocoaPods тоже).
4. Установить `pnpm` и Node 22 (как для основного проекта).

## 2. Сборка проекта
```bash
cd apps/ios_flutter
tool/setup_ios.sh     # создаёт ios/, ориентация, ATS, иконка, PrivacyInfo
tool/sync_web.sh      # собирает игру и кладёт её в assets/www
flutter run           # на симуляторе или подключённом iPhone
```
После **каждого** изменения игры снова запускай `tool/sync_web.sh`.
`BUNDLE_ID=com.твоё.имя tool/setup_ios.sh` — если нужен другой bundle id.

## 3. Apple Developer (платно, 99 $/год)
- Аккаунт: https://developer.apple.com/programs/ — **тебе 12 лет, оформляет родитель/опекун**.
- В Xcode: `open ios/Runner.xcworkspace` → Runner → Signing & Capabilities → выбрать Team.
- Файл `ios/Runner/PrivacyInfo.xcprivacy` добавить в таргет Runner (File → Add Files…).
- App Store Connect → My Apps → «+» → New App (bundle id из Xcode).

## 4. Выпуск
```bash
flutter build ipa --release
```
Загрузить `build/ios/ipa/*.ipa` через Transporter или Xcode → Organizer → Distribute.
Сначала TestFlight (внутреннее тестирование), потом «Submit for Review».

## 5. Что нужно заполнить в App Store Connect
| Поле | Значение |
|---|---|
| Privacy Policy URL | страница политики из репозитория My-Projects (`privacy-policy.kc.html`, нужно включить GitHub Pages) |
| Support URL | `support.kc.html` оттуда же |
| Скриншоты | iPhone 6.7" и 6.5" в **горизонтали** (1 + хотя бы 3 штуки), iPad если поддерживаем |
| Возрастной рейтинг | фэнтези-насилие мультяшное, без покупок и рекламы |
| App Privacy | «Data Not Collected», если онлайн-аккаунты не используются (см. риски) |
| Экспорт-шифрование | уже `ITSAppUsesNonExemptEncryption=false` |

## 6. Риски отказа при проверке (честно)
1. **4.2 «Минимальная функциональность»**: чистая обёртка сайта отклоняется. Здесь игра **встроена и работает офлайн**, это сильный аргумент. В заметке для ревьюера написать: «Игра полностью работает без сети, контент хранится в приложении».
2. **5.1.1(v) Удаление аккаунта**: если в приложении можно создать аккаунт, удаление должно быть **внутри приложения**. Сейчас аккаунты убраны из меню, поэтому лучше **полностью отключить онлайн-вход** в версии 1.0 либо добавить удаление.
3. **Вход через Google**: требует и «Вход через Apple». В оболочке нативного моста (`window.webkit.messageHandlers.auth`) нет, кнопка Google скрыта, так что риска нет, пока Google не включён.
4. **Онлайн-режим**: приложение работает с Supabase; убедись, что проект включён и RLS-политики применены (см. `supabase/`). Рабочий онлайн без развёрнутого бэкенда = отказ «Crashes/Bugs».
5. **Дети**: у приложения нет аналитики и рекламы, но если в онлайн-режиме есть имена игроков, Apple может спросить про модерацию (в лобби уже есть фильтр ников и только английский).
6. **Web Workers (ИИ)**: проверить на реальном iPhone, что воркеры стартуют; при ошибке игра переключается на запасной путь, но медленнее.
