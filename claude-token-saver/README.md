# token-saver v2 для Claude Code

**Режет шум в выводе инструментов и учится на твоих сессиях: какие строки Claude реально использует, какие настройки для какой команды лучше, когда пора `/compact`.**

## Что внутри

| Файл | Роль |
|---|---|
| `pre_tool.py` | PreToolUse: оборачивает шумные Bash-команды в фильтр, определяет **семейство** (test, build, lint, install, git, search, files, logs); видит «добор» скрытого |
| `run_filtered.py` | Чистит вывод, режет середину, **выбирает, какие скрытые строки показать**, пишет полный лог, возвращает тот же код выхода |
| `scorer.py` + `labels.py` | **ML №1.** Онлайн-логрегрессия на хэш-признаках (чистый Python). Метки берутся из transcript: что Claude процитировал или нашёл grep/sed по логу |
| `tuner.py` | Stop-хук: после каждого хода учит модель строк, делает шаг MCTS **отдельно для каждого семейства**, прогнозирует контекст |
| `haiku.py` | **ML №2, выключен по умолчанию.** Дайджест огромных выводов и «учитель» для локальной модели. Жёсткие лимиты |
| `ctxpred.py` | **ML №3.** Онлайн-регрессия роста контекста, предупреждение про `/compact` |
| `agents/output-filter.md` | Субагент на Haiku для чтения больших файлов и логов |
| `install.py` | Ставит всё, правит `settings.json` и `CLAUDE.md` (бэкап, идемпотентно) |

## Установка

```
python3 install.py --dry-run     # посмотреть итоговый settings.json
python3 install.py               # в ~/.claude, потом перезапустить Claude Code
python3 install.py --haiku       # то же + включить Haiku (см. ниже)
python3 install.py --uninstall
```

Через `env` ставятся: `MAX_THINKING_TOKENS=10000`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50`, `CLAUDE_CODE_SUBAGENT_MODEL=haiku`, `MAX_MCP_OUTPUT_TOKENS=8000`. Если `model` не задана, ставится `sonnet`. Твои значения не перезаписываются (кроме `--force`).

## Как это учится

```
ход Claude → хуки пишут события → Stop → tuner.py:
  1. transcript → метки «эта строка лога понадобилась» → дообучить модель строк
  2. (Haiku вкл.) иногда Haiku размечает лог → ученик учится у него
  3. награда на семейство = сэкономленный вывод − 0.15×«добор» − 0.5×доля цитат, которых не было на экране
     → шаг MCTS → новый конфиг этого семейства в config.json (действует со следующей команды)
  4. размер контекста из transcript → прогноз роста → предупреждение пользователю
```

- **Метки бесплатны:** редкий идентификатор из лога (путь, имя теста, номер, `snake_case`), который Claude назвал в ответе или вызове инструмента, или строки, найденные `grep`/`sed` по сохранённому логу. Содержимое `tool_result` в метки не идёт.
- **Модель строк** заменяет regexp «error/failed…», когда набрала 20 положительных меток. Видит то, что regexp не видит (например `reconcile_mismatch`), и перестаёт тратить место на «шумные» совпадения.
- **Настройки на семейство:** у `pytest` и `git log` оптимальная степень обрезки разная, у каждого своё дерево.

```
python3 ~/.claude/token-saver/tuner.py --status      # что выучено: семейства, recall модели vs regexp, Haiku
python3 ~/.claude/token-saver/tuner.py --freeze      # зафиксировать конфиги (--unfreeze, --reset)
python3 ~/.claude/token-saver/tuner.py --haiku on    # включить/выключить Haiku (off)
```

Выключить фильтр целиком: `"wrap_enabled": false` в `~/.claude/token-saver/config.json` (действует сразу).

## Haiku (по умолчанию выключен)

Тратит твои токены и в песочнице не проверен вживую, поэтому включается явно.

| Что | Лимит |
|---|---|
| Дайджест | только для вывода ≥ 32 000 символов (~8k токенов), ответ ≤ 12 строк |
| Учитель | с вероятностью `0.3 × (1 − согласие ученика)`, минимум 0.02: чем лучше локальная модель, тем реже зовём Haiku |
| На сессию | ≤ 10 вызовов, ≤ 300k токенов (оценка по длине текста) |
| Вход одного вызова | ≤ 120k символов (голова + хвост) |
| Бэкенд | `claude_cli` (`claude -p --model haiku`, лимит подписки), `api` (`ANTHROPIC_API_KEY`), `cmd` (своя команда) |

Дочерний `claude -p` запускается с `TOKEN_SAVER_INNER=1`: все хуки при этом молча выходят, рекурсии нет. Если Haiku недоступен или отдал ошибку, фильтр работает как без него.

## Что проверено, а что нет

Проверено (32 теста, `cd tests && python3 -m unittest test_core test_ml`):
- **Скорер:** на синтетических логах ловит нужные строки, которые regexp не видит (recall@4: 1.00 против 0.00); калибровка и сохранение работают.
- **Метки:** цитаты, grep/sed по логу, шум в `tool_result` игнорируется.
- **Сквозной сценарий:** фильтр → transcript → Stop: пропущенная цитата снижает награду ровно на 0.5, после 5+ меток фильтр сам начинает спасать такие строки.
- **MCTS** по семействам изолирован, на симуляции сходится.
- **Контекст:** ошибка прогноза падает с 0.83k до 0.31k токенов за ход, предупреждение приходит около порога, с паузой между ними.
- **Haiku:** лимиты, защита от рекурсии, fallback при сбое, падение частоты вызовов (0.30 → 0.01) при росте согласия.
- **Скорость:** разбор transcript на 40 МБ — 0.03 с (читается хвост), фильтр на 200k строк — ~0.4 с, накладные ~60 мс на команду.

**Не проверено в живом Claude Code** (в песочнице его нет):
1. Формат ответа хука (`updatedInput` + `permissionDecision`), формат transcript (`message.usage`, `timestamp`, блоки `tool_use`) и поле `systemMessage` у Stop-хука сделаны по документации и по моему знанию формата. Если transcript устроен иначе, метки и прогноз контекста молча не заработают (останутся regexp и MCTS).
2. Флаги `claude -p --model haiku` и то, как Haiku-вызов считается в лимите.
3. Всё это на реальных данных: на симуляции модель учится быстро, на твоих сессиях нужно ~20+ ходов с обрезанным выводом, пока она заменит regexp. Смотри `--status`: когда `recall model` стабильно выше `regex`, модель работает.

## Ограничения

- **`/compact` из хука выполнить нельзя.** Пакет предупреждает, когда контекст подходит к порогу (50% окна), а раннее автосжатие делает `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`.
- Фильтруются только простые команды из белого списка. Всё с `&&`, `;`, `|`, `>`, `$()` и фоновые запуски идут без изменений. Экономит только вывод инструментов, историю чата и размышления модели не трогает.
- Для переписанной команды хук отдаёт `permissionDecision: "allow"`; по документации правила `deny` и `ask` он не обходит. Не нравится: `"wrap_permission": "none"`.
- Метки шумные (цитата ≠ обязательно нужно). Поэтому модель учится на сотнях логов, а не на единицах, и поэтому есть `--status` для контроля.
- Нужен `bash` в PATH (на Windows это Git Bash, который Claude Code и так использует) и Python 3.8+.
